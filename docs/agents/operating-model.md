# Multi-agent operating model

## Purpose

Use native Codex subagents and isolated worktrees to shorten independent work while keeping one accountable integration path. Agents own artefacts, not fictional titles or meetings.

## Roles and concrete outputs

| Role | Owns | Required output |
|---|---|---|
| Lead orchestrator | Master specification, breakdown, dependencies, integration, gates, rework, milestone acceptance | Plan, ownership map, integrated package, validation record, owner decision list |
| Product research | Competitors, user reports, market gaps, principles, prioritisation evidence | Dated/cited research with evidence classes, uncertainty, and NextSet implications |
| Fitness domain | Terminology, programme structures, set types, progression, substitution, edge cases, safety | Versioned rules, decision tables, validations, tests, no-claim boundaries |
| UX | IA, journeys, repeated-task efficiency, onboarding, programme creation, recovery and empty/error states | Complete flows and acceptance criteria, with friction removed or justified |
| Visual design | Identity, exactly three directions, tokens, motion, haptics, prototypes, originality | Source visuals, specifications, ten screens per direction, evaluation and recommendation |
| Architecture | Stack, boundaries, data model, local-first, offline, migrations, future sync, privacy | Weighted evaluation, diagrams/specifications, ADRs, risks, spike gates |
| Quality | Test strategy, acceptance, accessibility, performance, offline/data-loss cases | Measurable matrices, budgets, evidence requirements, go/no-go gates |
| Independent reviewer | Challenge completed work without primary authorship | Severity-ranked findings, coverage gaps, rework verification, final gate result |

## Operating cycle

1. Lead records scope, phase boundary, dependencies, ownership, file boundaries, and completion evidence.
2. Independent workstreams use separate worktrees or non-overlapping file ownership. Shared schemas are proposed before concurrent editing.
3. Each specialist returns artefacts plus sources, commands, validation, uncertainty, and unresolved decisions.
4. Lead integrates terminology, identifiers, cross-links, and decisions; it does not silently average conflicting recommendations.
5. Independent reviewer receives the integrated artefacts and original brief, not the lead’s desired verdict.
6. P0–P2 findings return to the responsible owner with exact acceptance evidence. Review repeats after rework.
7. Lead presents a decision package and stops at the phase boundary.

## Actual foundation workstreams

The foundation milestone used four bounded workstreams with non-overlapping ownership:

- Research: competitor, pain-point, interaction, non-fitness, tooling, and name-collision documents
- Product/domain/UX: PRD, feature inventory, journeys, rulebook, programme/set specifications, safety, edge cases, and domain tests
- Architecture/quality: stack evaluation, data/offline/sync/security, ADRs, testing, acceptance, accessibility, performance, and readiness
- Design/integration: visual sources, prototype system, design documentation, project governance, repository skills/templates, and cross-package validation

An independent review follows integration. This record describes work performed; it does not by itself prove quality.

## Communication

Agents report: outcome first; files/decisions; evidence and commands; limitations; decisions needed. They do not claim access, testing, visual review, push, or publication without direct evidence.
